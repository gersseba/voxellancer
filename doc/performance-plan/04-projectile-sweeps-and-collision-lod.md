# Step 4: Sweep projectiles with conservative collision proxies

## Goal

Reduce the repeated movement and voxel-tree collision work generated by fast,
small projectiles without allowing them to tunnel through targets.

## Baseline evidence

The [persisted baseline](../../benchmark-results/large-combat-vsync-baseline.json)
records **14.686 ms/frame** for projectile movement and collision in the
slowest three-second interval. This is nested inside the 19.154 ms/frame
movement-and-collision metric.

[`Movement`](../../src/physics/movement.cpp) subdivides movement into steps and
checks voxel collisions at each step. This makes high projectile counts and
long per-frame projectile travel especially costly.

## Planned change

Prototype a projectile-specific swept segment/capsule query against conservative
ship bounds. Use the spatial index to produce a small candidate list, then run
voxel-level collision only for likely contacts. Keep collision filters and
damage application authoritative; use conservative bounds so the broadphase
cannot discard a real hit.

Use lower collision fidelity only for candidate rejection, not by changing
floating-point position precision or simply increasing the movement step.
Retain the existing path as a comparison/fallback until hit equivalence is
established.

## Assumed improvement

Hypothesis: reduce the projectile-movement metric by **30-60%**, approximately
**4.4-8.8 ms/frame** in the baseline's worst window. Confidence is low-to-medium:
the profiler identifies projectile movement as a large cost, but does not yet
separate substep count from voxel-tree traversal. The estimate overlaps the
parent movement metric and Step 3.

## Validation

- Add tests for fast, grazing, overlapping, and multi-target projectile paths.
- Compare hit/miss counts, damage, projectile lifetime, and voxel collision
  pairs against the current implementation over fixed-seed scenarios.
- Measure projectile substeps, broadphase candidates, and voxel narrow-phase
  calls as well as frame timings.
